# ConfigCompany — ربات فروش VPN + مینی‌اپ + پنل مدیریت

## نصب (یک دستور، مثل x-ui)
با SSH وارد سرور شوید (`ssh root@IP_SERVER`؛ در ویندوز PuTTY/Termius) — اوبونتو/دبیان/CentOS با دسترسی root، **دامنه‌ای که به IP سرور اشاره می‌کند** لازم است (مینی‌اپ تلگرام فقط HTTPS می‌پذیرد؛ گواهی را Caddy خودکار می‌گیرد):
```bash
bash <(curl -Ls https://raw.githubusercontent.com/YOUR_USER/configcompany/main/install.sh)
```
> اول پروژه را در GitHub خودتان آپلود کنید و `YOUR_USER` را عوض کنید (یا `CC_REPO=...` بدهید). بدون GitHub: zip را روی سرور باز کنید و `sudo bash install.sh` بزنید.

نصب‌کننده Docker را نصب می‌کند و فقط این‌ها را می‌پرسد: دامنه، توکن ربات، شناسه‌ی تلگرام شما، (اختیاری) پنل VPN و زرین‌پال. رمزها را خودش می‌سازد، سرویس‌ها را بالا می‌آورد، بکاپ روزانه را زمان‌بندی می‌کند و آدرس‌ها + توکن ورود پنل را چاپ می‌کند.
حالت غیرتعاملی: `CC_YES=1 CC_DOMAIN=vpn.example.com CC_BOT_TOKEN=... CC_ADMIN_ID=... bash install.sh`

### مدیریت (مثل میرزا: همه چیز از داخل SSH)
بعد از نصب فقط `configcompany` را بنویسید (یا دوباره دستور نصب را بزنید) تا منو باز شود: وضعیت، ریستارت، لاگ، آپدیت، **خروجی دیتابیس به تلگرام**، **ورود دیتابیس**، **بکاپ خودکار** (۶/۱۲/۲۴ ساعت)، **تمدید SSL**، تغییر دامنه، تغییر توکن ربات، افزودن ادمین، ویرایش تنظیمات، توکن ورود پنل، حذف کامل.
زیردستورها: `configcompany status|restart|log|update|export|import <file>|autobackup|ssl|bot|admin|token|settings|domain|uninstall`
بکاپ‌ها در `/opt/configcompany/backups` (۱۴ تای آخر) و روزانه به تلگرام مدیر هم ارسال می‌شود.

## لیست امکانات
✅ **انجام‌شده:** مینی‌اپ تلگرام (خرید/تمدید، کیف پول، QR اشتراک، رفرال، تنظیمات) · ربات (`/start`، اعلان‌ها، تأیید پرداخت) · پنل مدیریت (کاربران، پلن‌ها، پرداخت‌ها، نمایندگان، تخفیف/پیشنهاد، محتوا، تحلیل فروش، تنظیمات) · نمایندگان با ربات جدا · پلن‌های چندمدته · اکانت تست و تبدیل خودکار به خرید · تمدید خودکار · دسترسی موقت (grace) · کد تخفیف/کد هدیه/گروه تخفیف/پیشنهاد ویژه · رفرال سه‌سطحی (پول یا روز) + نمایش شبکه · زرین‌پال و کارت‌به‌کارت · حالت تعمیر (دستی و خودکار) · مانیتورینگ ترافیک و هشدار · اعلان مدیر به تفکیک دسته · بکاپ خودکار · ساخت کاربر دستی بدون تلگرام · صفحه‌ی لندینگ · آداپتر Remnawave/Marzban(PasarGuard) · تست خودکار، Alembic، rate limit، CI.
❌ **عمداً/هنوز نیست:** ورود OAuth و کابین وب جدا از تلگرام · درگاه‌های روسی و رسید مالیاتی Nalogo · RBAC ریزدانه (فقط master/agent) · حالت مولتی‌تعرفه · لیست و حذف دستگاه (HWID) در مینی‌اپ · اتصال مستقیم به 3x-ui · ایمیل.


هسته‌ی واقعی برای مینی‌اپ و پنل مدیریت: کاربر، پلن، کیف پول، خرید، رفرال، کد تخفیف/هدیه، اکانت تست، تایید پرداخت.

## اجرا
```bash
cp .env.example .env      # BOT_TOKEN, JWT_SECRET, ADMIN_TG_IDS را پر کنید
docker compose up -d --build
# مستندات تعاملی: http://localhost:8000/docs
```
بدون Docker (تست سریع): `pip install -r requirements.txt && DATABASE_URL=sqlite:///./configcompany.db DEV_ALLOW_UNSIGNED=1 uvicorn app.main:app --reload`

## اتصال به پنل
`PANEL=mock` (توسعه) | `remnawave` | `marzban` (برای PasarGuard هم امتحان کنید).
آداپترها در `app/panel/` هستند و فقط دو متد دارند: `upsert` و `get`. مسیرهای API را با نسخه پنل خودتان تطبیق دهید.

## رابط کاربری (همراه پروژه)
- مینی‌اپ: `https://YOUR_DOMAIN/miniapp/` ← این آدرس را در BotFather به‌عنوان Mini App / منوی ربات ثبت کنید (HTTPS لازم است).
- پنل مدیریت: `https://YOUR_DOMAIN/admin-ui/` ← توکن ادمین: `docker compose exec api python -m app.cli token <tg_id>`
- تست محلی مینی‌اپ بدون تلگرام: `DEV_ALLOW_UNSIGNED=1` و باز کردن `/miniapp/?dev=1`
- نودها/Hostها/Core را از خود پنل Remnawave یا PasarGuard مدیریت کنید؛ پنل ConfigCompany بخش فروش را کنترل می‌کند.

## جریان ورود (مینی‌اپ)
1. مینی‌اپ `Telegram.WebApp.initData` را به `POST /auth/telegram` می‌فرستد (امضا HMAC بررسی می‌شود).
2. توکن JWT برمی‌گردد؛ بقیه درخواست‌ها با هدر `Authorization: Bearer <token>`.
3. لینک رفرال: `https://t.me/<bot>?startapp=ref_<code>`

## منطق کسب‌وکار
- تخفیف دوره: ۳ ماه ۸٪، ۶ ماه ۱۵٪، ۱۲ ماه ۲۵٪ (`config.py`)
- ابتدا پنل صدا زده می‌شود؛ اگر خطا بدهد پولی کسر نمی‌شود.
- کمیسیون رفرال پلکانی (۸/۱۲/۱۸٪)؛ پاداش به‌صورت پول یا روز اشتراک طبق انتخاب معرف.

## درگاه پرداخت (زرین‌پال)
`ZARINPAL_MERCHANT` و `PUBLIC_URL` را در `.env` بگذارید. مینی‌اپ دکمه‌ی «پرداخت آنلاین» را خودکار نشان می‌دهد.
کاربر پرداخت می‌کند ← callback روی `/pay/zarinpal/callback` ← verify ← شارژ کیف پول (idempotent) ← پیام ربات.
کارت‌به‌کارت هم هست: درخواست با دکمه‌ی تأیید/رد مستقیم به پیام‌خصوصی ادمین‌ها می‌رود.

## ربات تلگرام (داخل همین سرویس، long polling)
`/start` (با پشتیبانی `ref_…`)، `/sub`، `/balance`، دکمه‌ی منوی Mini App، تأیید/رد پرداخت توسط ادمین، اعلان‌ها.
نکته: فقط با **یک worker** اجرا کنید (پیش‌فرض Dockerfile همین است)؛ برای مقیاس بالاتر ربات را webhook کنید یا جدا اجرا کنید.

## کارهای زمان‌بندی‌شده (`app/jobs.py`، هر ۳۰ دقیقه)
- تمدید خودکار: کاربران دارای `auto_renew` که کمتر از ۲۴ ساعت به انقضایشان مانده، با همان پلن و مدت آخرین خرید از کیف پول تمدید می‌شوند.
- یادآوری انقضا (۳ روز مانده) و هشدار موجودی ناکافی؛ حداکثر روزی یک بار برای هر کاربر.

## نمایندگان و چندمستأجری
- مدیر کل (`ADMIN_TG_IDS`) از پنل ← «نمایندگان» نماینده می‌سازد: شناسه تلگرام، نام، **توکن ربات اختصاصی**، تخفیف عمده و کمیسیون.
- هر نماینده ربات خودش را دارد (همین سرویس همه‌ی ربات‌ها را poll می‌کند). مینی‌اپ یکی است؛ `initData` با توکن همان رباتی که مینی‌اپ را باز کرده اعتبارسنجی می‌شود و کاربر به همان نماینده تعلق می‌گیرد.
- نماینده با همان آدرس `/admin-ui/` وارد می‌شود (فقط مشتریان خودش را می‌بیند): داشبورد، کاربران، پرداخت‌های مشتریانش.
  - **ساخت/تمدید دستی** مشتری (بدون تلگرام) با قیمت عمده از موجودی نماینده کسر می‌شود.
  - **کمیسیون** درصدی از خریدِ مشتریان ربات او به موجودی‌اش اضافه می‌شود.
  - شارژ کارت‌به‌کارت مشتریان او را خودش (در ربات یا پنل) تأیید می‌کند.
  - رفرال فقط داخل مشتریان همان نماینده کار می‌کند.
- مدیر کل می‌تواند بدون تلگرام هم کاربر بسازد (حجم و مدت دلخواه، رایگان) و کاربر را حذف کند (آرشیو می‌شود، تاریخچه مالی می‌ماند).
- لینک دعوت: `https://t.me/<bot>?start=ref_<code>` (از طریق `/start` ربات ثبت می‌شود).
- برای ربات هر نماینده، در BotFather منوی Mini App را روی `PUBLIC_URL/miniapp/` بگذارید (خود سرویس هم با `setChatMenuButton` این کار را می‌کند).

## دسترسی موقت، تبدیل تست، رفرال سه‌سطحی (قابل تنظیم از پنل ← تنظیمات)
- **دسترسی موقت (grace):** کاربر منقضی‌شده‌ی دارای پلن یک بار می‌تواند N روز دسترسی بگیرد (`POST /me/grace`)؛ با خرید بعدی دوباره فعال می‌شود.
- **تبدیل خودکار تست به خرید:** اگر ادمین یک پلن انتخاب کند، پس از پایان تست و در صورت کافی بودن موجودی کیف پول، همان پلن خودکار خریداری می‌شود؛ وگرنه فقط یادآوری (روزی یک بار).
- **رفرال:** سطح ۱ پلکانی (۸/۱۲/۱۸٪ بر اساس تعداد دعوت)، سطح ۲ و ۳ درصد ثابت؛ هر معرف پاداشش را پول یا روز اشتراک می‌گیرد. `GET /referral/network` شمار هر سطح و فهرست دعوت‌شده‌های مستقیم را برمی‌گرداند.

## تست، Alembic، rate limit
- **تست:** `pip install -r requirements.txt -r requirements-dev.txt && pytest -q` (۴۳ تست: امضای initData، قیمت و تخفیف، کوپن، خرید، خطای پنل بدون کسر پول، grace، رفرال سه‌سطحی، نماینده و دسترسی‌ها، تأیید پرداخت). GitHub Actions در `.github/workflows/test.yml` همین را اجرا می‌کند.
- **Alembic:** برای تولید جدی `USE_ALEMBIC=1` بگذارید. بار اول: `docker compose run --rm api alembic revision --autogenerate -m init`، فایل ساخته‌شده در `alembic/versions/` را نگه دارید و commit کنید؛ از آن به بعد `start.sh` خودش `alembic upgrade head` را اجرا می‌کند. بعد از هر تغییر مدل: `alembic revision --autogenerate -m "توضیح"`.
- **Rate limit:** ورود/پرداخت ۲۰ درخواست در دقیقه و بقیه ۲۴۰ در دقیقه برای هر IP (`app/ratelimit.py`). پشت reverse proxy مورد اعتماد (nginx/Caddy) `TRUST_PROXY=1` بگذارید تا IP واقعی از `X-Forwarded-For` خوانده شود. حافظه‌ای است، پس با یک worker سازگار است.

## عملیات: تعمیر، مانیتورینگ، اعلان، بکاپ (پنل ← تنظیمات)
- **حالت تعمیر:** دستی یا **خودکار**. هر ۲ دقیقه سلامت پنل بررسی می‌شود؛ دو شکست پیاپی = تعمیر خودکار و اعلان به مدیر، و با برگشت پنل خودکار برداشته می‌شود. در تعمیر فقط خرید/شارژ/تست/grace بسته است (مینی‌اپ بنر نشان می‌دهد؛ مدیر کل مستثناست و callback درگاه همچنان کار می‌کند).
- **مانیتورینگ ترافیک:** هر ۳۰ دقیقه مصرف از پنل خوانده می‌شود. مصرف بیش از آستانه (`anomaly_gb`) بین دو بررسی = هشدار «مصرف غیرعادی» به مدیر؛ رسیدن کاربر به ۹۰٪ حجم = هشدار به خود کاربر (روزی یک بار).
- **اعلان مدیر به تفکیک دسته:** پرداخت جدید، کاربر جدید، قطع/وصل پنل، مصرف غیرعادی؛ هرکدام جدا روشن/خاموش می‌شود.
- **بکاپ:** روزانه در ساعت تنظیم‌شده (UTC) به تلگرام مدیران ارسال می‌شود (SQLite: کپی سازگار؛ PostgreSQL: `pg_dump -Fc`، بازیابی با `pg_restore --clean -d <url> فایل.dump`). حد تلگرام ۵۰MB است. دکمه‌ی «بکاپ همین حالا» هم هست. ایمیج Docker کلاینت `postgresql-client` را دارد (نسخه‌اش باید ≥ نسخه‌ی سرور باشد).

## تخفیف، پیشنهاد ویژه، محتوا، تحلیل (پنل)
- **گروه تخفیف:** درصد ثابت برای کاربران خاص. **پیشنهاد ویژه:** زمان‌دار، برای همه/منقضی‌ها/کاربران جدید، با دکمه‌ی «ارسال به کاربران» در ربات. قیمت = پایه × تخفیف دوره × max(گروه، پیشنهاد) × کوپن.
- **محتوا:** FAQ، قوانین، حریم خصوصی، متن خوش‌آمد ربات (`{name}`) و اخبار صفحه‌ی اصلی مینی‌اپ؛ همه از پنل ← محتوا.
- **تحلیل فروش:** درآمد روزانه، سفارش، کاربر جدید، ARPU، تبدیل، پلن‌های پرفروش (نماینده فقط مشتریان خودش را می‌بیند).
- **امنیت:** نام و متن‌های کاربر‌ساخته (نام تلگرام، شماره پیگیری، یادداشت تراکنش) در پنل و مینی‌اپ escape می‌شوند تا XSS و سرقت توکن ادمین ممکن نباشد.
